## Review queue priority

1. Developer productivity: GitHub/GitLab, issues, pull requests, CI, code review, build and deployment.
2. Knowledge and collaboration: search, browser, documents, drive, email, calendar, Slack and Notion.
3. Operations: cloud, containers, Kubernetes, infrastructure, monitoring, logs, metrics and tracing.
4. Data: PostgreSQL/MySQL/Redis, storage, filesystem, analytics and vector search.
5. Business automation: CRM, payments, finance, ticketing, notifications, workflow, scheduler, queue and webhooks.
6. Security and quality: vulnerability databases, SAST/DAST, dependency/SBOM, license, provenance and test automation.

No candidate should move from OBSERVED to INSTALLED/CONNECTED/READY without evidence-backed review and Core approval.

## Detail inspection capability

The Workspace also provides an `Inspect metadata` action per candidate. It calls the authenticated read-only endpoint `GET /api/tools/discovery/mcp-registry/details?name=namespace%2Fserver&version=latest`. The endpoint returns bounded package, transport, repository and remote-host metadata; it withholds secret values, runtime arguments, full remote URLs and non-allowlisted repository URLs. It does not install, register, launch or execute any candidate.
