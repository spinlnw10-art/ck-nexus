## Maintenance rules

1. Add new canonical documents to the relevant section above.
2. Keep one current source of truth for live operational and release status; mark older records as historical.
3. Do not move or rename documents until inbound links, workflows, checksum manifests, package assets and release evidence references are checked.
4. Keep evidence and audit records immutable where required; prefer additive corrections and explicit supersession notes.
5. Do not treat roadmap, prototype, validation-subset or historical documents as Production approval.
